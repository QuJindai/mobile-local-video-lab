# V0.8.1 — handset feedback

## Uploaded V0.8 sample

The user supplied two screenshots and an MP4 after installing the V0.8 feature build. The visible selected recipe is **crane up, gentle, 33 single-course frames, 8 FPS, forward/backward loop**. The title/version is cropped; the installed package/version and signing identity cannot be independently established from these screenshots.

The actual MP4 fully decodes as H.264 / YUV420P, **528×720, 64 frames, 8.000 seconds**, with uniform 0.125-second presentation intervals. No adjacent decoded frames are byte-identical. After suppressing codec noise by downsampling and spatial smoothing, all 31 return frames have their closest forward-frame match at the expected index `64 - output_index`. Inspected frames at the beginning, middle, turn and end show rising camera motion and return. These observations support the sample's timing/loop behavior; they do not establish independent subject animation, all-preset quality or smooth playback on every device.

Raw numeric evidence: [v0.8.0-handset-video.json](evidence/v0.8.0-handset-video.json). User portraits, screenshots and video bytes are not copied into the repository. Generation time, temperature, filesystem destination and the exact share-intent path were not measured from the uploaded file.

## System bar overlap

Both screenshots still show scrolling content beneath system bars. The old listener added system-bar padding to the inner vertical content, so that space scrolled away. V0.8.1 instead places the ScrollView inside a fixed FrameLayout whose padding consumes the system-bar/cutout area geometrically; clipping remains enabled. The inner content retains only its ordinary spacing. A light app theme explicitly uses dark status/navigation icons for the light background.

Reference: [Android guidance on system bars and display-cutout insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge). This implementation retains the fixed inset area while the content scrolls. The fix still needs handset visual confirmation; compilation/source review alone is not visual acceptance.

Version is 0.8.1 / code 10 with the existing application ID and signing certificate. The already tested generation pipelines, model downloads and history formats are unchanged. MobileI2V remains unqualified and no full model pack is included.

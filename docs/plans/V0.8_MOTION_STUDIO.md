# V0.8 Motion Studio

User request: upgrade features and deliver one installable APK for the existing Samsung test device. Continue on a feature branch; preserve main and draft PR #4.

## Scope

- Six depth camera paths: left/right parallax, push in, arc orbit, crane up, pull back. Five independently warped keyframes share one depth estimate and one original image. RIFE interpolates between keyframes.
- Three motion strengths with a conservative crop margin. Depth animation moves the viewpoint; it does not generate new subject actions or objects.
- 9/17/33/49 source frames, an optional forward/backward loop without duplicated turning frames, and an accurate duration preview. MobileI2V remains fixed at 17 frames and does not inherit these controls.
- Correct the pinned RIFE directory sampler: its original `count / numframe` mapping repeatedly holds the final input. Use endpoint-inclusive mapping for both old two-image paths and the new five-keyframe path.
- Keep result history, export/share, download/import, stable application ID and signing. Record the selected recipe with new history entries while retaining legacy history compatibility. Fix backend-specific labels and system-bar overlap.
- MobileI2V precision gates and MNN OpenCL production constraints remain in effect. No qualified full model package exists in this version.

## Implementation and validation

1. Pure Java camera pose and output sequence models; exercise layer motion, arc reversal, crop bounds, strength scaling, loop ordering, duration, and legacy history.
2. Render keyframes one at a time to disk; reuse the existing bounded PNG-to-MP4 encoder. Do not keep a full bitmap sequence in Java memory.
3. Patch only the pinned native scheduling block with a shared C++ sampler; compile and execute host regressions before Android builds.
4. Integrate UI, metadata, version 0.8.0/code 9 and CI. Independently review changes, run JVM/native gates, build and verify APK content, signature and source identity.
5. Deliver one APK. Device motion quality and Samsung codec behavior remain handset verification items; host tests do not establish them.
